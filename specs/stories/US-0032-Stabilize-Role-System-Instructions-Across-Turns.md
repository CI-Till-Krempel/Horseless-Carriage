# User Story

- Story ID: US-0032
- Title: Stabilize Role System Instructions Across Turns (ADK Prompt-Cache Alignment)
- Status: Done
- Priority: Must
- Owner: Architect
- Last Updated: 2026-11-12

## As a team member running a sprint through `adk web`, I want every role's system instruction to stay byte-identical for the lifetime of a session, so Gemini's implicit prompt cache stays aligned and `adk web` never shows the "System instructions were modified between consecutive turns" performance alert.

## Acceptance Criteria
- Given any of the six shipped roles' `LlmAgent`s (ProductOwner, ScrumMaster, DevTeam, QA, Architect, ScrumOrchestrator), when the real ADK instruction-building pipeline (`google.adk.flows.llm_flows.instructions._build_instructions`) runs twice for the same role with two different `session.state` snapshots (simulating two turns within one sprint conversation), then the resulting `llm_request.config.system_instruction` is byte-identical both times.
- Given `agents/scrum_team/agent.py`, when a role's `LlmAgent` is constructed, then its static guardrails/workflow/DOD/DOR text (`agents/scrum_team/prompts.py`'s `*_PROMPT` constants) is passed via ADK's `static_instruction=` field, not `instruction=` - so ADK never runs it through `google.adk.utils.instructions_utils.inject_session_state` (the regex-based live `{var_name}` -> `session.state[var_name]` substitution that `instruction=` is always subject to for a plain string, per `LlmAgent.canonical_instruction`).
- Edge case: genuinely dynamic, per-turn-fresh content (sprint/budget status, sprint phase, role identity/customization) continues to flow through the existing `before_model_callback`-injected `llm_request.contents` path (`sprint_status_injection_callback`, `phase_awareness_injection_callback`, `role_identity_injection_callback`) - never through `system_instruction` - so this fix does not regress any of that behavior.
- Edge case: a steering-change PR (`propose_steering_change`) that merges a new `<Role>-identity.md` into the product/state repository mid-sprint must not retroactively change an already-running session's identity content - confirmed unaffected by this fix: `role_identity_injection_callback` already reads that file from disk only once per session (gated on `len(llm_request.contents) > 1`), so an in-flight session keeps what it loaded at session start and only a new session picks up the change.

## Notes
- Root cause (GH-515): `agents/scrum_team/agent.py`'s six `LlmAgent` constructions previously passed each role's static prompt text via ADK's `instruction=` field. For a plain string, `LlmAgent.canonical_instruction` always sets `bypass_state_injection=False` (true only for a callable `InstructionProvider`), so `google/adk/flows/llm_flows/instructions.py:_process_agent_instruction` unconditionally runs the text through `google.adk.utils.instructions_utils.inject_session_state` on *every single model call* - a regex (`{+[^{}]*}+`) that live-substitutes any `{identifier}`-shaped substring matching a real `session.state` key. Our prompt text already contains incidental `{"status": "error", ...}` (every role's `*-guardrails.md`) and `{"spike": true}` (`DevTeam-workflow.md`) JSON examples that happen not to parse as valid state names today (`inject_session_state`'s own `_is_valid_state_name` rejects anything containing quotes/colons/commas) - a fragile accident, not a guarantee: any future prompt edit adding one bare `{word}` matching a real state key (e.g. documenting `{sprint_number}` in prose) would have silently started baking live, per-turn-varying state directly into the system instruction, breaking the model's implicit prompt cache exactly as the real `adk web` user in GH-515 observed.
- Fix: switch all six `LlmAgent`s (`agents/scrum_team/agent.py`) from `instruction=<ROLE>_PROMPT` to `static_instruction=<ROLE>_PROMPT`. `static_instruction` is ADK's own documented mechanism for exactly this case (`LlmAgent.static_instruction`'s docstring: "for content that never changes and doesn't contain placeholders... sent directly to the model without any processing or variable substitution... primarily for context caching optimization") - it is appended straight to `system_instruction` via `llm_request.append_instructions()`, with no call to `canonical_instruction`/`inject_session_state` at all, making it structurally impossible for any of these prompts to vary between turns within one session regardless of future prompt-text edits.
- Investigated and ruled out as contributing causes: (1) `prompts.py`'s `_load_role_prompt`/module-level `*_PROMPT` constants are computed once at process import time, not re-read per turn or per session - a steering-change PR landing mid-session cannot retroactively change them; (2) every `before_model_callback` that injects dynamic content (`sprint_status_injection_callback`, `phase_awareness_injection_callback`, `role_identity_injection_callback`) inserts `role="system"` `types.Content` into `llm_request.contents`, which `google.adk.models.lite_llm._content_to_message_param`/`_to_litellm_role` converts to an ordinary `"user"`-role message, not the dedicated `system_instruction` field the `adk web` cache-alignment check diffs - so none of these ever touch `system_instruction` at all, dynamic or not.

## Test Approach
- `agents/scrum_team/tests/test_agent.py::TestSystemInstructionCacheStability`:
  - `test_every_role_uses_static_instruction_not_dynamic_instruction` - structural assertion that every shipped agent's `static_instruction` equals its `prompts.py` constant and `instruction` is unset.
  - `test_production_agents_produce_identical_system_instruction_across_turns_with_different_state` - runs the real ADK instruction-building pipeline for every role twice, with two very different `session.state` snapshots (sprint number/goal, budgets, token usage), asserting byte-identical `system_instruction` both times.
  - `test_a_bare_state_placeholder_in_a_dynamic_instruction_would_have_broken_cache_alignment` - isolates the bug mechanism itself with a throwaway agent/prompt containing a real state-key placeholder, proving `instruction=` produces different text per turn while the identical text via `static_instruction=` does not.
