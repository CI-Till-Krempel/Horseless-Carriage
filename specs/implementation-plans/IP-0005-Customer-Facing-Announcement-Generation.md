# Implementation Plan

- Plan ID: IP-0005
- Title: Customer-Facing Announcement Generation
- Epic: EP-0005
- Status: Draft
- Owner: Product Owner
- Last Updated: 2026-07-16

## 1. Objective
Produce a draft, external, non-technical release announcement for every release, sourced from the changelog rather than authored freehand.

## 2. Approach
The template scaffolding (`spec-templates/announcements/README.md`, `TEMPLATE-ANNOUNCEMENT.md`) already exists as of this planning pass (US-0015, done). Add a `generate_announcement` tool that reads the changelog entry generated by IP-0004, filters out internal-only items (refactors, test-only changes, tooling), and translates the remainder into user-facing benefit language following `TEMPLATE-ANNOUNCEMENT.md`'s structure. Write the result to `specs/announcements/ANNOUNCEMENT-{version}.md` in the target repo. Update `PO_PROMPT` to make invoking this tool mandatory during Sprint Review.

## 3. Affected Components / Files
- New: `agents/scrum_team/tools/announcements.py` (or a new function in `tools/docs.py`).
- `agents/scrum_team/prompts.py` — `PO_PROMPT` ("SPRINT REVIEW & RELEASE" block).
- Reads: IP-0004's changelog output.

## 4. Steps / Milestones
1. Confirm/finalize `TEMPLATE-ANNOUNCEMENT.md` structure (already done, US-0015).
2. Implement `generate_announcement`: parse changelog entries, classify user-facing vs. internal-only, draft announcement content (US-0016).
3. Handle the "no changelog yet" case by reporting that drafting isn't possible yet, rather than fabricating content.
4. Update `PO_PROMPT` to require this call during Sprint Review, with an explicit "no announcement needed" acknowledgment path for releases with no user-facing changes (US-0017).

## 5. Testing / Verification
- Unit tests per US-0016 acceptance criteria (classification correctness, missing-changelog handling).
- Prompt-content review for US-0017 (not independently unit-testable); optionally an integration test simulating a sprint-review pass and asserting the tool is invoked.

## 6. Risks & Mitigations
- Risk: internal/user-facing classification is imperfect (e.g. a security fix framed too technically). Mitigation: this produces a *draft* for human/PO review, not an auto-published announcement.
- Risk: prompt-only enforcement (US-0017) can still be skipped by the LLM despite instructions, echoing this project's existing pattern of unenforced "MANDATORY" prompt text. Mitigation: track as a known limitation; a stronger code-level enforcement (analogous to EP-0003 for PR scope) could be a future follow-up ADR if this proves insufficient in practice.

## 7. Rollout / Rollback
- New, additive tool plus a prompt-text change. Rollback is removing the tool call and reverting the prompt text; no schema/data migration.
