# Horseless Carriage v0.2.1

- Release: v0.2.1
- Audience: customers
- Status: Published
- Released: 2026-11-12

## Pitch
Horseless Carriage gives an LLM a simulated Scrum team — Product Owner, Scrum Master,
Dev, QA, and Architect — that plans, builds, and ships real code against your actual
GitHub repo.

## Headline
A patch release: three reliability fixes the team performance evaluation harness
caught - two of them in code your own sprints run too, not just the eval - and one
fix to the eval tooling itself so it actually evaluates the branch you ask it to.

## Fixes & Improvements
- **A sprint can no longer crash outright if a role writes a story's `user_story`
  field as a structured object instead of plain text.** `advance_story_stage`/
  `upsert_story` now reject that cleanly and ask for a fix, instead of the whole
  session dying with an unhandled error.
- **A release PR can no longer deadlock retrying forever over the framework's own
  generated `CHANGELOG.md` entry.** The release step now cleans up after itself before
  the next git operation, instead of leaving that file in a state that made every
  retry fail the exact same way.
- **The evaluation harness's own stopped-early explanations are more accurate.** When
  a sprint runs out of its event/duration budget rather than its retry allowance, the
  report now says so instead of always blaming "a retry ceiling," and calls out when
  raising the token budget specifically won't help.
- **Manually re-running the team performance evaluation against a specific branch now
  actually evaluates that branch**, instead of silently falling back to `main`
  regardless of which branch was picked in the GitHub Actions dispatch dialog.
