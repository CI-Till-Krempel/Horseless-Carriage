# Horseless Carriage v0.2.0

- Release: v0.2.0
- Audience: customers
- Status: Published
- Released: 2026-11-10

## Pitch
Horseless Carriage gives an LLM a simulated Scrum team — Product Owner, Scrum Master,
Dev, QA, and Architect — that plans, builds, and ships real code against your actual
GitHub repo.

## Headline
v0.2.0 turns Horseless Carriage from "one project, one checkout" into a real
multi-project tool with a cockpit to watch it all — and starts teaching the team to
fix itself instead of just reporting what's wrong.

## What's New
- **Run as many projects as you want, from one checkout.** `new_project.py` installs
  Horseless Carriage into any repo as a submodule — each one gets its own ports,
  container names, and state, so nothing collides, and every install is remembered
  automatically.
- **A live dashboard for all of them.** One page lists every project you've set up —
  status, current sprint phase, budget, product version — with one-click start/stop
  and live health checks on each project's LiteLLM and agent UI links.
- **Releases now write their own story.** `create_release_pr` generates a real
  `CHANGELOG.md` entry from what the sprint actually shipped, drafts a customer-facing
  announcement from it (this one's a live example), and Dev Team ships end-user guides
  alongside the code instead of after it.
- **The team can learn from its own retros, for real.** When a retrospective finds a
  gap in how a role behaves — not a code bug, a prompt gap — Scrum Master must ship a
  concrete fix via `propose_steering_change` before the sprint is allowed to close. No
  more "noted, we'll do better" with nothing behind it.
- **Nothing raised in a retro quietly disappears.** Every retro now checks back on
  open items and steering proposals from prior sprints, and escalates to a human
  anything that was promised but never actually landed.
- **Foundations for a self-serve toolchain.** The Architect can propose a project's own
  workbench setup (installing a JDK, Gradle, whatever the stack needs) as a real,
  human-reviewed PR — and, like every steering change, the team can propose it but can
  never merge it themselves.
- **Setup got friendlier.** Registering a GitHub App is now a guided, click-twice flow
  instead of hand-copying IDs and keys, and `doctor.py` can create a missing
  main/develop branch for you instead of just telling you to.
