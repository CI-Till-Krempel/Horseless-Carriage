# Manual Test Plan — v0.1.0

**Purpose:** a human walkthrough of everything the automated suites (`python3
run_tests.py`, the eval harness) can't fully verify on their own — real
interactive prompts, real Docker Desktop behavior, real GitHub pushes/PRs,
and cross-platform quirks. Run this before cutting `release/v0.1.0` → `main`
(see [RELEASE.md](../RELEASE.md)).

**How to use this document:** work through each test case in order within a
suite; suites can be split across testers/machines. Mark each row Pass/Fail,
and for any Fail, open an issue and link it in the Notes column. A release is
blocked if any **Critical** case fails; **High** failures need an explicit
call from whoever owns the release; **Medium** failures can ship with a
tracked follow-up issue.

**What counts as a release-blocking bug:** data loss or corruption in the
state repository, the agent bypassing a documented safety gate (budget caps,
DoD/DoR enforcement, protected-branch pushes), a setup/doctor script crashing
with a raw traceback instead of a clear message, or `python3 run_tests.py`
failing on a clean checkout. Cosmetic/wording issues are not release-blocking
on their own.

## Test environment checklist

Before starting, have available:
- [ ] One **macOS or Linux** machine with Docker Desktop (or Docker Engine) installed
- [ ] One **Windows** machine with Docker Desktop installed (real Windows, not WSL2-as-the-shell — see [docs/SETUP.md § Setting up on Windows](../docs/SETUP.md))
- [ ] Real API keys for at least 2 of the 3 cloud providers (Gemini, Anthropic, OpenAI) — low-spend/sandboxed keys are fine, these tests make real (tiny) billed calls
- [ ] `gh` CLI installed and authenticated on each machine, with push/PR access to a disposable scratch GitHub repo created just for this test pass
- [ ] Enough free disk (~5-10 GB) for an Ollama model pull, if testing the local stack
