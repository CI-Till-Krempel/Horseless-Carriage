# Customer-Facing Announcements

Use this section to draft external, non-technical release announcements.

Guidelines
- Written for end users/customers, not engineers — avoid internal jargon, ticket IDs, or implementation detail.
- One announcement per release; name it after the version it accompanies.
- Draw content from the release's changelog and sprint report, but translate it into user-facing value ("what you can now do"), not a list of commits.
- Keep it short enough to read in under a minute.

Templates
- TEMPLATE-ANNOUNCEMENT.md — Structure for a single release announcement.
