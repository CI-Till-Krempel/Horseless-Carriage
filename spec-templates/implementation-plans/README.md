# Implementation Plans

Use this section to capture the concrete technical execution plan for an Epic before/while work begins.

Guidelines
- One Implementation Plan per Epic. Reference the Epic ID it belongs to.
- Keep it updated as the approach changes during implementation.
- An Implementation Plan is distinct from an ADR: an ADR records *why* a decision was made (context, options, consequences); an Implementation Plan records *how* it will be executed (steps, affected files, testing, rollout). Link to relevant ADRs rather than duplicating their rationale.

Templates
- TEMPLATE-IMPLEMENTATION-PLAN.md — Objective, approach, affected components, milestones, testing, risks, and rollout for a single epic.
