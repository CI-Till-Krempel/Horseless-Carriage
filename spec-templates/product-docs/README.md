# Product Documentation

Use this section to capture end-user, how-to-use-the-product documentation — distinct from `../requirements` (internal PRD/SRS specs, written for the team) and `../architecture` (ADRs, written for engineers).

Guidelines
- Write for the person using the product, not the person building it.
- Structure around tasks the user wants to accomplish, not internal module boundaries.
- Update product docs in the same PR as the user-facing change they describe (per the Definition of Done).

Templates
- TEMPLATE-USER-GUIDE.md — Structure for a single how-to/user-guide document.
